Three structural changes. Renamed in the same release: fg-* → text-* (matching Atlassian/Carbon/Polaris), the five "for use on inverted" tokens → -on-inverse, and radius-10 → radius-control-md. Compound <family>-fg tokens (action-primary-fg, ai-fg) deliberately keep -fg: there it means "the foreground paired with this fill", Material's onPrimary concept, not a position on the text scale. Icons keep a dedicated family, matching Atlassian, Carbon and Polaris (Material 3 is the outlier that unifies them). But only icon-primary carries its own value — one ramp step lighter than text-primary, because a stroke icon reads heavier than a glyph at equal value. The other 8 alias fg-*/status-*, so the API exists without the old system's hand-maintained 80% duplication. Borders drop numeric steps and paired hovers for named weights, encoding hover by ladder position (default → strong) rather than a suffix. Surface hovers became alpha overlays that composite over any fill, which is why the old system needed a solid hover per surface and the new one needs two overlays total.

The count grew 70 → 104. The growth is in families the old system had no equivalent for: action-* (20), icon-* (9), ai-* (5), glass-* (7), emphasis-* (4), viz-* (8). Old button colours lived in a flat button-* family of 18; those became action-*.

icon + text both at text-primary icon at icon-primary, text at text-primary

Status went from 2 roles to 4. Old had only error and success — no info or warning at the semantic layer. Each new role carries three renderings (deepened text, pale tint, mid solid), so old text-error #e6483d splits: the deepened status-danger #B23230 for text, and status-danger-bg-solid #DB504D keeps the old brighter value for fills.

Identity marks

colour-coding removedwas 16 category tokens

Was — 8 hash-assigned hues

Billing Infra Design Research

Now — one neutral treatment

Billing Infra Design Research

Retired: category-1…8-bg / -text (16 tokens) plus the purple/teal/magenta ramps that only existed to feed them (33 primitive steps). Avatars, taxonomy Badges/Chips and calendar dots now take bg-sunken + text-secondary.

Why. The hue was assigned by hashing a label, so category-5 meant "hash slot 5" — no meaning, and an undocumented stability contract: changing the hash, the slot count or a label would silently recolour every existing tag. Against §1.1's rule that colour is a scarce resource spent only on meaning, an arbitrary hash hue is decoration. Identity reads from shape (squared avatar = agent, round = human) and the label, which were always the load-bearing channels.

Fill carries the static/interactive split — filled = static, outlined = interactive. That frees shape on Badge (pill default or rounded, one per view) while Chip is always cornered. Old code could make either shape on either component, which is why shape could never be the signal. Retired: Badge outline + neutral solid (became Chip's single-select state), Chip category. Multi-select selected takes no fill — border.selected is 19.9:1 against the rest border's 1.13:1, so the near-black outline + ✓ carry it without weight. purple/slate/outline/active had zero real usage — squashed.

Size names invert: old sm/md/lg 20/24/28 vs new md/lg 20/24. A literal md → md shrinks a badge; dropping the prop lands correctly.
