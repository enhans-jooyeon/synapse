# Synapse changelog

Versioning is **release-based** (design.md §6): ongoing work lands under **Unreleased**; the version bumps only when a release is cut for the team.

## Unreleased

- **AppLauncher gets a faux-glass surface (opaque frosted, no `backdrop-filter`).** To evoke the macOS-Launchpad frosted look without reversing the §5 glass-deprecation: the launcher panel now uses an OPAQUE frosted tint (`glass.surface`) + a top inner-rim highlight (`glass.rim`, `inset 0 1px 0`) + soft `glass.border`. It *reads* as glass but inherits nothing from behind — **`backdrop-filter` stays forbidden (SY015)**, and the translucency tokens (`glass.blur`/`glass.filter`, `shadow.glass`) remain dormant. Rationale: real blur over an austere mostly-white app reads muddy, which is why glass was dropped in the first place. The `glass.*` tokens are reactivated in this opaque form (light: cool luminous near-white; dark: graphite lifted above `bg.raised`). Updated: `tokens/synapse.css` + `tokens/synapse.tokens.json` (glass group), `foundations.md` §5, `components.md · AppLauncher`, `preview.html`.

- **AppLauncher redesigned icon-forward — tiles are now custom-icon image wells, not outlined Cards.** Matching the AgentOS prototype's launchpad intent: the panel is airier (`radius.2xl`, header `heading-lg` title + right-aligned pill search, `system apps` / `your apps` sections), and each app is a 56px squircle **image well** + name beneath, with no bordered card. The well clips whatever a published app supplies (`object-fit: cover`) via a fallback ladder — **user-generated custom icon → graphite `bg.inverse` monogram → system glyph** — with an inset `border.subtle` hairline so light custom icons stay defined; empty slots are pale `bg.sunken` squircles. Key doctrine line: the launcher's **own chrome stays achromatic** (panel, labels, frame, system-app marks); color lives ONLY inside a user-supplied app icon, so the icon generator can output arbitrary color without it leaking into the system. Replaces the previous "outlined `Card` tile" definition. Updated: `components.md · AppLauncher`, `preview.html`. (Aligns with the graphite point-color direction below.)

- **Point color retargeted blue → graphite (achromatic, mode-inverting accent).** The system's single accent, formerly the point blue `#0621C4`, is now graphite that **inverts by mode** (near-black `#1A1A1F` in light, near-white `#F2F2F4` in dark) so the one point moment reads on either background — matching the ElevenLabs/Sana benchmark direction. Because the accent inverts, its foreground inverts with it: `action.brand-fg` and `category.point-fg` flip (white in light, near-black in dark), and the AI-marker + Composer-send glyphs were re-routed from `fg.on-solid` (constant white, shared with status solids) to the inverting `action.brand-fg`. The `"fg-on-solid on ai-solid"` gate contrast pair became `"action-brand-fg on ai-solid"`. **The functional blue ramp is unchanged by decision** — `fg.link` and `border.focus` stay blue, so blue now lives only in hyperlinks/focus, never in CTAs or AI markers. Trade-off: the "AI at work" beacon (`ai.solid`) is no longer blue — AI-at-work reads by shape/context. Touched: `tokens/synapse.css` (both modes), `tokens/synapse.tokens.json` (primitive `point` ramp → graphite + light steps for inversion, semantic modes, de-blued descriptions), `preview.html`, `tools/validate.py`. See `proposals/2026-07-28-point-color-graphite.md`. **Follow-up:** `foundations.md` §1 accent prose still frames the point as blue.

- **Icon family switched Lucide → Tabler Icons (outline set).** The closed concept→icon registry (`icons.md`) now maps every concept to a Tabler outline glyph, stroke down-weighted from Tabler's 2px default to Synapse's 1.5 (sizes 16/20/24 unchanged). Coverage is complete — all ~90 concepts resolve to a real Tabler glyph, including `webhook`, `keyboard`, and the run/play family that the alternative (Iconoir) couldn't cover. Name changes of note: `house`→`home`, `menu`→`menu-2`, `arrow-up-right`→`external-link`, `circle-help`→`help-circle`, `chart-column`→`chart-bar`, `table-2`→`table`, `building-2`→`building`, `languages`→`language`, `log-out`→`logout`, `check-check`→`checks`, `trash-2`→`trash`, `refresh-cw`→`refresh`, `rotate-cw`→`rotate-clockwise`, `list-filter`→`filter`, `ellipsis`→`dots`, `square`→`player-stop`, `play`→`player-play`, `pause`→`player-pause`, `pen-line`→`edit` (refine), `mic`→`microphone`, `refresh-ccw`→`refresh-dot`, `arrow-right-left`→`arrows-exchange`, `maximize-2`→`maximize`, `undo-2`/`redo-2`→`arrow-back-up`/`arrow-forward-up`, `circle-play`→`player-play` (run; Tabler has no circled-play), `key-round`→`key`, `image`→`photo`, `info`→`info-circle`, `triangle-alert`→`alert-triangle`, `circle-alert`→`alert-circle`, `file-chart-column`→`report`, `message-square`→`message`, `trend-up`/`trend-down`→`trending-up`/`trending-down`, `thumbs-up`/`thumbs-down`→`thumb-up`/`thumb-down`. `send` stays `arrow-up` (keeping the composer's up-arrow-in-circle affordance rather than adopting Tabler's paper-plane). The reply/undo collision is resolved (`corner-up-left` for reply, `arrow-back-up` for undo). The custom brand **agent glyph** is unchanged. Updated: `icons.md`, `foundations.md` §7, referencing glyph names in `components.md`/`ai-patterns.md`/`content.md`/`recipes.md`, and the manifest. **Follow-up:** `app-generation/component-catalog.html` still loads the Lucide runtime (`data-lucide`) and needs a separate migration to Tabler's consumption method.

- **Overlays are opaque — glassmorphism explored and dropped.** A dark/two-tint glass material was prototyped for the CommandPalette, AppLauncher, and follow-up panel, but a translucent surface inherits whatever's behind it (muddy on a light app, a heavy slab when dark) and forces every child element onto per-surface restyling — the cost outweighed the effect in an austere, mostly-light product. Final state: **CommandPalette and AppLauncher are opaque `bg.raised` panels over a `bg.scrim` backdrop** (radius `lg`, `border.default`, `shadow.modal`) — the scrim provides separation on a light app; the **follow-up panel is opaque `bg.raised`** (`shadow.overlay`). **`backdrop-filter` is now forbidden (SY015).** The `glass.*` tokens + `shadow.glass` remain in the token file but are **deprecated / dormant** (retained only for a possible future inverse-surface context). foundations §5, the component specs, `design.md` §8 never-list, and `preview.html` all reflect the opaque overlays.
### Radius + spacing refresh — softer, roomier (visual benchmark vs ElevenLabs / Sana AI)

Token-value retune from the visual-benchmark pilot (`proposals/2026-07-24-radius-spacing-refresh.md`). Borders-first structure, achromatic palette, and black primary are unchanged; no component API changes.

- **Finer 6-step radius scale** (was 5-step, which forced chunky insets): `xs` 4 (tiny insets) · `sm` **8** (nested elements — segments, menu items, quote) · `md` **12** (controls, menus, trays) · `lg` **16** (cards) · `xl` **20** (modals/drawers) · `2xl` **24** (section shells, new) · `full`. Component references re-pointed up one step so approved pixel values hold: buttons/inputs/chips = 12, cards = 16, modals = 20.
- Buttons adopt **rounded 12px** corners (pill was rejected — clashes with the square icon-only buttons). Menus land at **12** (not 16 — read too round).
- **Concentric-corner rule preserved with slim 4px insets** (the earlier attempt inflated insets to 8/12/16, which read chunky — the finer scale fixes the root cause): SegmentedControl (well 12, segments 8, inset 4, height 32), Menu (panel 12, items 8, inset 4), Composer tray (12, quote 8, inset 4). Calendar popover → 12 (day cells concentric-exempt).
- **Spacing:** `control.padding-x` 12→16px, `control.gap` 8→12px. Card/page/section spacing and table density unchanged — tables stay dense on purpose.
- Docs synced — `foundations §185/§189`, `components.md` (SegmentedControl, Menu, Composer, ProposalCard), `ai-patterns §5/§18`; storybook + `preview.html` re-pointed; manifest rebuilt; gate green.

### Optical corrections — padding balance + leading-icon trim

- **`control.padding-x` 16 → 12px.** The earlier 16 read side-heavy against the ~11px vertical inset at 36px control height (≈1.5×); 12 balances it (≈1.1×). Roominess stays in the radius, not fat sides. Fixes Input/Button/Select proportion.
- **Leading/trailing icon trim generalized.** The Button-only rule (a 16px stroke icon's internal whitespace makes symmetric padding read icon-heavy → trim that side −2px) is now a sanctioned optical exception in `foundations §3`, applying to Select/Combobox/DatePicker triggers, Menu items, nav items, Chips, Tabs, Banner, Toast. Reference impl trims nav/menu rows (left 8→6).
- **Chip side padding evened** (`.rel-chip` 4×12 → 4×8) — the 3× side-heavy ratio brought in line.
- These join the existing optical corrections (badge 1px nudge, SourceChip numeral, thumbs ±1px translate), which were untouched.

## 1.0.2 — 2026-07-24 — harness anatomy: tools, memory + twin components

Fills out the missing harness-anatomy elements (tools, memory) and adds the components the AgentOS digital twin surfaced. No breaking changes; existing tokens/rules unchanged.

- **Memory element — the correction ledger** (`docs/process/correction-ledger.md` + `feedback/` + `synapse digest`): the harness's memory, pointed at the **maintainers**, not the generator (a generator-facing memory would be a shadow contract — durable lessons belong promoted into `design.md`/the gate). Each reviewed screen gets a `synapse-corrections` block captured **in the PR** (embedded in `.github/PULL_REQUEST_TEMPLATE/ui_review.md`): one `category | attribution | severity | source | note` line per fix needed to reach shippable, with closed field sets so entries aggregate. `synapse digest` rolls the collected blocks up into a pattern report — separating the harness-actionable signal (`llm-generation`/`contract-gap`/`gate-gap`) from taste and requirement churn, and flagging categories that recur (≥2) as **DS-gap candidates** to take to the refinement register. Auto-detectable fixes (token/state/provenance) come from the diff+gate; only the un-lintable ones are hand-tagged. Wired into `design-cycle.md` (Review captures, Refine consumes). GitHub-PR auto-harvest lands once the connector is authorized; interim, blocks are dropped into `feedback/`.

- **Five component types added (52 → 57)**, extracted from the AOS digital twin (`proposals/2026-07-23-twin-component-candidates.md`) and specified to the Synapse contract — spec-only, not yet implemented in `storybook/`:
  - **GraphCanvas · FlowNode · Edge** — the node-graph editor for the Workflow / Pipeline / Ontology-Link builders (the biggest prior `workbench` coverage gap).
  - **RunLog** — hierarchical execution log (run → step → line).
  - **PivotTable** — cross-tab aggregation for dashboards.
  - **AssistantPanel** — the docked/floating global agent (composite).
  - **AppLauncher** — the app tile-grid overlay.
  - Manifest rebuilt; `build_manifest.py` `C` set extended in lockstep.
  - Added `preview.html` component-browser stories (token-only demos + When/Avoid/Anti/Where guidance) for all five, so they show in the browser.
- **New recipe R16 · Builder workbench shell** — the reusable `workbench` layout the Workflow, Pipeline, and dev-stage Replay/CUA builders share (generalizes the twin's replay-shell screens, which are too app-specific to be components). Also **reconciled the recipe cap**: the screen-intent schema and manifest recipe set were stuck at R1–R12 while `recipes.md` already defined R13–R15 — extended both to **R1–R16** (and the intake skill) so all recipes are actually declarable. Also filled the **preview.html Recipes group**: it demoed only 4 recipes (R1/R4/R6/R9); added token-only stories for the other 12 (R2/R3/R5/R7/R8/R10–R16) so all 16 show in the browser.
- **New harness CLI — `tools/synapse.py`** (the "tools" harness element): `lookup <name>` verifies a component/token/recipe/archetype is real and prints its rules — or the closest matches if not (prevents off-manifest components (RC6) and off-token values (RC3) *at generation time*, not just at the gate); `validate <intent.json>` and `gate` wrap `validate.py`; `list` prints a closed set. Wired into `screen-intake-skill.md` and `design-cycle.md` so the generating agent calls it. Stdlib-only; wrap-able as an MCP server later.
- **External-tools stance** documented in `design-cycle.md` (§Tools): the process is **strictly code-based** — no Figma/Canva or design-inspiration boards. The one sanctioned external tool is **bounded web reference research** — a *capability* (web search + viewing a live UI reference), tool-agnostic: fulfilled by whatever the generation tool provides or, at the floor, a human-supplied URL/screenshot, so it's not Claude-bound. The only hard tool dependency is bash (for `tools/synapse.py`). It may inform *structure/interaction* in Frame and maintainer refinement only — never visual style, never Generate directly, never Intake's data — and must clear the refinement rubric's Tier B (so it can't smuggle in consumer-app polish).
