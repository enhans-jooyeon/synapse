# Synapse changelog

Versioning is **release-based** (design.md §6): ongoing work lands under **Unreleased**; the version bumps only when a release is cut for the team.

## Unreleased

- **Added a semantic `padding` token layer + `radius-none` (referenced BeyondUI's Padding/Radius token frames).** Rather than copy BeyondUI's px-alias padding set (which would duplicate the spacing scale in code), added an **intent-named padding scale that aliases the space primitives**: `--sy-padding-{none,2xs,xs,sm,md,lg,xl}` → `{primitive.space.*}` (md=16px, lg=24px, …), so padding reads by role and can't drift from spacing. Existing role paddings (`control-padding-x`, `card-padding`, `page-padding`) are unchanged. On radius, kept Synapse's `xs…2xl/full` scale (BeyondUI's `xxxs…xxxxl` naming is more awkward and the scale was just reworked) and filled the one real gap — **`radius-none` (0)** for squared corners; skipped BeyondUI's 32/48 (no element exceeds `2xl` 24 in an enterprise app). Updated: `tokens/synapse.tokens.json` (primitive.radius + semantic.padding), `tokens/synapse.css`, `foundations.md` §3/§5. Gate green.

- **Spacing tokens renamed to the Tailwind 4px-multiplier index (breaking, names only).** The `--sy-space-*` scale moved from literal-px names (`space-16` = 16px) to **Tailwind-style index** names (`space-4` = 16px; name × 4px = value). Rationale: px-literal names collide with an LLM's Tailwind priors — the model reads `4` as 16px — and silently emit wrong sizes the gate can't catch (a valid-but-wrong token). **Pixel values are unchanged; this is purely a naming change.** Map: 2→`0_5` · 4→`1` · 6→`1_5` · 8→`2` · 10→`2_5` · 12→`3` · 16→`4` · 20→`5` · 24→`6` · 28→`7` · 32→`8` · 40→`10` · 48→`12` · 64→`16` · 80→`20` · 96→`24` · 128→`32` · 160→`40` · 192→`48` · 224→`56` · 256→`64` · 320→`80` · 384→`96`. The three sub-grid fine steps use an underscore (`space-0_5` = 2px, `space-1_5` = 6px, `space-2_5` = 10px) because a dot is invalid in a CSS custom-property name. Executed as one **atomic single-pass rename** (1104 refs across `tokens/synapse.css` + `.tokens.json`, `preview.html`, the specs, and storybook), which sidesteps the crossover collision (old `space-16`→`space-4` while old `space-64`→`space-16`); every used token verified defined, gate green. `foundations.md` §3 documents the convention. Stack is CSS-variable-based (not Tailwind), so this is a var rename, not a Tailwind-config change. Supersedes + archives `proposals/2026-07-28-spacing-multiplier-rename.md`. **Breaking for any consumer referencing `--sy-space-*` by name.**

- **Doc cleanup sweep — purged lingering old-system references from the live docs.** Swept the contract + reference set for superseded conventions (Lucide, the point blue `#0621C4`, Iconoir, `radius-control`, "10px never allowed", the removed density modes). Fixed the last stragglers: a stale `#0621C4` in a `preview.html` Button story, and `HANDOFF.md`'s stale facts (the gate line still read "spacing scale … NOT 10"; the point color was still described as blue). Contract specs, tokens, `foundations.md`, `docs/`, `storybook/`, README, and `product-context.md` verified clean. Intentionally **not** rewritten: `CHANGELOG.md` and `proposals/archive/` (historical records). **Still lingering — `app-generation/`** (the ECharts catalog): 17 `data-lucide` runtime refs and 63 `#0621C4` chart-color uses — a separate migration, not a find-replace (its blue is a chart data-ramp, and it loads the Lucide JS runtime).

- **Spacing scale extended to match the BeyondUI / Tailwind primitives (adds `10` + `128`→`384`).** Referenced BeyondUI Premium v4.1's spacing primitives (via Figma) against Tailwind's default scale. Added **`space-10`** (aligns the fine end to 8/10/12 — Tailwind's `2.5`) and the large steps **`128, 160, 192, 224, 256, 320, 384`**, capped at 384 (Tailwind's ceiling); BeyondUI's 512/640/768 were dropped as dead weight in a 760px-content app. Retired the "10px NEVER allowed" clause in `foundations.md` §3 — the low end is now explicitly a 2px fine grid (2/6/10). `1` stays as the sanctioned hairline-offset exception. Updated: `tokens/synapse.tokens.json` + `tokens/synapse.css` (space group), `tools/validate.py` (`SPACE_SCALE`), `foundations.md` §3. Gate green; manifest rebuilt.

- **Foundations tidy — Radius is now its own section (§5), separated from Elevation.** The radius doctrine (scale, size-relative control radius, concentric-corner rule) lived inside the old §5 "Elevation & borders"; it's been extracted into a dedicated **§5 Radius** so spacing, radius, and elevation are cleanly separate. Renumbered: Elevation & borders → §6 · Motion → §7 · Iconography & illustration → §8 (§7.1 → §8.1) · Accessibility → §9 · Keyboard → §10. All `foundations §N` cross-references were rewired across specs, gate messages, tokens, and preview — the `§5` citations *split* (the concentric-corner rule stays §5; overlay/glass/shadow refs moved to §6). No rule content changed, only its location + numbering. Gate green; manifest rebuilt.

- **Control radius is now size-relative (default 10px), retiring the "one fixed radius per component" rule.** The 4px-step refresh had put every control at `md` (12px), which read too round on 32–36px buttons and inputs — and a component with `sm`/`md`/`lg` size variants shouldn't carry one radius across all of them. Added **`radius-10` = 10px** to the scale (a plain value step, not a semantic token — t-shirt names kept for the rest per preference) and made control radius scale with size: `sm` → `sm` (8) · default → `10` · `lg` → `md` (12); the smaller Chip (24px) stays `sm` (8). Buttons, inputs, and Select/Combobox triggers now default to 10. Cards (`lg` 16), modals (`xl` 20), menus/trays and SegmentedControl (`md` 12) are unchanged. Reconciled the gate: `validate.py` `RADIUS_SCALE` was stale (`{4,8,10,16,24}` — missing 12/20) and is now `{4,8,10,12,16,20,24,9999}`. Retired the contradictory Button rule ("radius other than `sm`") and the "radius is always sm" guide line. Updated: `tokens/synapse.tokens.json` + `tokens/synapse.css` (new token), `foundations.md` §Radius, `components.md` (Button sizes/forbidden, Input), `tools/validate.py`, `preview.html` (`.btn`/`.btn-sm`/`.btn-lg`/`.field input` + guide).

- **Illustration promoted to a shared, scoped visual language (`foundations.md` §7.1).** Prompted by a generation that produced on-brand line-art spot illustrations (an isometric node-cube, an image placeholder, a design-system card): the icon line doctrine + the new EmptyState sub-spec had guided the *style*, but nothing governed it as a reusable language. Codified one — **1.5px-stroke line art in the icon language, achromatic** (`fg.secondary` + `border.default` faint marks; `status.danger` for error), now with a **light neutral fill tier** (`bg.sunken`/`bg.surface` only — no saturated, brand, or gradient fills). **Scope is a closed tier:** EmptyState, the Guided archetype (onboarding/first-run heroes + feature-intro cards), and full-page status states — the same tier that already permits pill buttons and `lg` Badges; forbidden in dense/data/repeated/chrome surfaces. An optional single action badge (a registry icon in a graphite `bg.inverse` circle) is allowed where the surface exists to perform one action. Motifs stay governance-gated. **Gradient/atmospheric backdrops are explicitly out of scope** — the example's blue-gradient card was a hand-added custom, not harness-sanctioned; gradients remain forbidden. Updated: `foundations.md` §7 (renamed "Iconography & illustration" + new §7.1), `components.md` (EmptyState now references the shared language; light fill allowed), `patterns.md` (Guided archetype), and the preview component-browser guide. The three EmptyState spots were then regenerated in this filled hero-card style — two-tone neutral fills (`bg.page`/`bg.surface` faces over `bg.sunken` recesses) plus a single stacked layer for depth — matching the reference feature cards; the fill-tier wording was widened to cover raised faces + recessed panels. A corner-treatment rule was added to §7.1 (corners follow the object, not the token radius scale — sharp/miter for geometric forms, lightly rounded for containers; default crisp over soft), and the spots were re-cut with smaller radii + miter joins to match the reference cube's precision. Two further rules per review: illustrations are **strictly neutral** (the error spot's red stroke was dropped — error reads by motif + Retry copy, not color), and **every spot must carry at least one visible neutral fill** (the old error connector was line-only and looked out of place, so it gained a `bg.sunken` fill like the others). A third pass: **ink is `fg.primary`** — outlines and content/writing lines are drawn in the ink color, with grey (`border.default`) reserved for depth only; **stacked/back layers may sit at a gentle angle** (the earlier flat de-rotation over-corrected — the "pixelated" back card is re-angled to match the reference cards); and **fills are used sparingly** — typically one element (e.g. only one of the error connector's two squares is filled) so the fill reads as a dynamic accent rather than flattening the drawing. The **first-use motif is object-specific** (it names the thing being created, not a generic container): the agent-list first-use was reworked from the inbox tray (which read "incoming mail") to the **registered agent glyph on a squared agent card with a create badge and an empty agent slot angled behind** (the "new agent" / create motif) using the real brand glyph path, not a placeholder star.

- **EmptyState refined — governed line illustrations replace the ring medallion.** The old medallion (a `bg.sunken` circle + two concentric hairline rings) had two faults: the rings were drawn as negative-inset pseudo-elements that overran their layout box and collided with the title, and the treatment was deliberately too quiet to anchor the state. Replaced with a **line-illustration** system, making EmptyState **v1's sole sanctioned illustration surface**: one spot per flavor in a single 1.5px stroke, achromatic (`fg.secondary` + `border.default` faint marks), from a **closed motif set** — first-use = inbox tray, no-results = magnifier, error = disconnected connector (`status.danger` stroke). The spot reserves its own box with `space-16` beneath, which fixes the overlap. This retires the `no illustrations in v1` rule **for EmptyState only** — ChoiceCard and every other component stay illustration-free, and new motifs are governance-gated (not improvised). Updated: `components.md` (EmptyState), `preview.html` (medallion CSS → `.eill`, the three stories, and the component-browser guide). Manifest rebuilt; gate green.

- **Banner + Toast radius `lg` → `md` (16→12px).** After the radius refresh, the card-scale `lg` read disproportionately round on these short, wide strips — a 16px corner is roughly a third of a ~40px strip's half-height. Dropped both to the control-tier `md`, and codified the reason in `foundations.md` §Radius so regenerations don't reintroduce it: *radius reads relative to height — short notice strips (Banner, Toast) sit at control height and take `md`, not the card `lg`; match radius to the element's shorter dimension.* Updated: `components.md` (Banner, Toast), `foundations.md`, `preview.html`.

- **AppLauncher gets a faux-glass surface (opaque frosted, no `backdrop-filter`).** To evoke the macOS-Launchpad frosted look without reversing the §5 glass-deprecation: the launcher panel now uses an OPAQUE frosted tint (`glass.surface`) + a top inner-rim highlight (`glass.rim`, `inset 0 1px 0`) + soft `glass.border`. It *reads* as glass but inherits nothing from behind — **`backdrop-filter` stays forbidden (SY015)**, and the translucency tokens (`glass.blur`/`glass.filter`, `shadow.glass`) remain dormant. Rationale: real blur over an austere mostly-white app reads muddy, which is why glass was dropped in the first place. The `glass.*` tokens are reactivated in this opaque form (light: cool luminous near-white; dark: graphite lifted above `bg.raised`). Updated: `tokens/synapse.css` + `tokens/synapse.tokens.json` (glass group), `foundations.md` §5, `components.md · AppLauncher`, `preview.html`.

- **AppLauncher redesigned icon-forward — tiles are now custom-icon image wells, not outlined Cards.** Matching the AgentOS prototype's launchpad intent: the panel is airier (`radius.2xl`, header `heading-lg` title + right-aligned pill search, `system apps` / `your apps` sections), and each app is a 56px squircle **image well** + name beneath, with no bordered card. The well clips whatever a published app supplies (`object-fit: cover`) via a fallback ladder — **user-generated custom icon → graphite `bg.inverse` monogram → system glyph** — with an inset `border.subtle` hairline so light custom icons stay defined; empty slots are pale `bg.sunken` squircles. Key doctrine line: the launcher's **own chrome stays achromatic** (panel, labels, frame, system-app marks); color lives ONLY inside a user-supplied app icon, so the icon generator can output arbitrary color without it leaking into the system. Replaces the previous "outlined `Card` tile" definition. Updated: `components.md · AppLauncher`, `preview.html`. (Aligns with the graphite point-color direction below.)

- **Point color retargeted blue → graphite (achromatic, mode-inverting accent).** The system's single accent, formerly the point blue `#0621C4`, is now graphite that **inverts by mode** (near-black `#1A1A1F` in light, near-white `#F2F2F4` in dark) so the one point moment reads on either background — matching the ElevenLabs/Sana benchmark direction. Because the accent inverts, its foreground inverts with it: `action.brand-fg` and `category.point-fg` flip (white in light, near-black in dark), and the AI-marker + Composer-send glyphs were re-routed from `fg.on-solid` (constant white, shared with status solids) to the inverting `action.brand-fg`. The `"fg-on-solid on ai-solid"` gate contrast pair became `"action-brand-fg on ai-solid"`. **The functional blue ramp is unchanged by decision** — `fg.link` and `border.focus` stay blue, so blue now lives only in hyperlinks/focus, never in CTAs or AI markers. Trade-off: the "AI at work" beacon (`ai.solid`) is no longer blue — AI-at-work reads by shape/context. Touched: `tokens/synapse.css` (both modes), `tokens/synapse.tokens.json` (primitive `point` ramp → graphite + light steps for inversion, semantic modes, de-blued descriptions), `preview.html`, `tools/validate.py`. See `proposals/2026-07-28-point-color-graphite.md`. The accent/point doctrine prose was then aligned to graphite across `foundations.md` §1, `design.md` §2/§3, `components.md`, `ai-patterns.md`, and the manifest source (`app-generation/` and `HANDOFF.md` still reference the old `#0621C4` — see follow-up below).

Coverage is complete — all ~90 concepts resolve to a real Tabler glyph, including `webhook`, `keyboard`, and the run/play family that the alternative (Iconoir) couldn't cover. - **Overlays are opaque — glassmorphism explored and dropped.** A dark/two-tint glass material was prototyped for the CommandPalette, AppLauncher, and follow-up panel, but a translucent surface inherits whatever's behind it (muddy on a light app, a heavy slab when dark) and forces every child element onto per-surface restyling — the cost outweighed the effect in an austere, mostly-light product. Final state: **CommandPalette and AppLauncher are opaque `bg.raised` panels over a `bg.scrim` backdrop** (radius `lg`, `border.default`, `shadow.modal`) — the scrim provides separation on a light app; the **follow-up panel is opaque `bg.raised`** (`shadow.overlay`). **`backdrop-filter` is now forbidden (SY015).** The `glass.*` tokens + `shadow.glass` remain in the token file but are **deprecated / dormant** (retained only for a possible future inverse-surface context). foundations §6, the component specs, `design.md` §8 never-list, and `preview.html` all reflect the opaque overlays.
### Radius + spacing refresh — softer, roomier (visual benchmark vs ElevenLabs / Sana AI)

Token-value retune from the visual-benchmark pilot (`proposals/2026-07-24-radius-spacing-refresh.md`). Borders-first structure, achromatic palette, and black primary are unchanged; no component API changes.

- **Finer 6-step radius scale** (was 5-step, which forced chunky insets): `xs` 4 (tiny insets) · `sm` **8** (nested elements — segments, menu items, quote) · `md` **12** (controls, menus, trays) · `lg` **16** (cards) · `xl` **20** (modals/drawers) · `2xl` **24** (section shells, new) · `full`. Component references re-pointed up one step so approved pixel values hold: buttons/inputs/chips = 12, cards = 16, modals = 20.
- Buttons adopt **rounded 12px** corners (pill was rejected — clashes with the square icon-only buttons). Menus land at **12** (not 16 — read too round).
- **Concentric-corner rule preserved with slim 4px insets** (the earlier attempt inflated insets to 8/12/16, which read chunky — the finer scale fixes the root cause): SegmentedControl (well 12, segments 8, inset 4, height 32), Menu (panel 12, items 8, inset 4), Composer tray (12, quote 8, inset 4). Calendar popover → 12 (day cells concentric-exempt).
- **Spacing:** `control.padding-x` 12→16px, `control.gap` 8→12px. Card/page/section spacing and table density unchanged — tables stay dense on purpose.
- Docs synced — `foundations §185/§189`, `components.md` (SegmentedControl, Menu, Composer, ProposalCard), `ai-patterns §5/§18`; storybook + `preview.html` re-pointed; manifest rebuilt; gate green.

### Optical corrections — padding balance + leading-icon trim

- **`control.padding-x` 16 → 12px.** The earlier 16 read side-heavy against the ~11px vertical inset at 36px control height (≈1.5×); 12 balances it (≈1.1×). Roominess stays in the radius, not fat sides. Fixes Input/Button/Select proportion.
- **Leading/trailing icon trim generalized.** The Button-only rule (a 16px stroke icon's internal whitespace makes symmetric padding read icon-heavy → trim that side −2px) is now a sanctioned optical exception in `foundations §3`, applying to Select/Combobox/DatePicker triggers, Menu items, nav items, Chips, Tabs, Banner, Toast. Reference impl trims nav/menu rows (left 8→6).
- **Chip side padding evened** (`.rel-chip` 4×12 → 4×8) — the 3× side-heavy ratio brought in line.
- These join the existing optical corrections (badge 1px nudge, SourceChip numeral, thumbs ±1px translate), which were untouched.

## 1.0.2 — 2026-07-24 — harness anatomy: tools, memory + twin components

Fills out the missing harness-anatomy elements (tools, memory) and adds the components the AgentOS digital twin surfaced. No breaking changes; existing tokens/rules unchanged.

- **Memory element — the correction ledger** (`docs/process/correction-ledger.md` + `feedback/` + `synapse digest`): the harness's memory, pointed at the **maintainers**, not the generator (a generator-facing memory would be a shadow contract — durable lessons belong promoted into `design.md`/the gate). Each reviewed screen gets a `synapse-corrections` block captured **in the PR** (embedded in `.github/PULL_REQUEST_TEMPLATE/ui_review.md`): one `category | attribution | severity | source | note` line per fix needed to reach shippable, with closed field sets so entries aggregate. `synapse digest` rolls the collected blocks up into a pattern report — separating the harness-actionable signal (`llm-generation`/`contract-gap`/`gate-gap`) from taste and requirement churn, and flagging categories that recur (≥2) as **DS-gap candidates** to take to the refinement register. Auto-detectable fixes (token/state/provenance) come from the diff+gate; only the un-lintable ones are hand-tagged. Wired into `design-cycle.md` (Review captures, Refine consumes). GitHub-PR auto-harvest lands once the connector is authorized; interim, blocks are dropped into `feedback/`.

- **Five component types added (52 → 57)**, extracted from the AOS digital twin (`proposals/2026-07-23-twin-component-candidates.md`) and specified to the Synapse contract — spec-only, not yet implemented in `storybook/`:
  - **GraphCanvas · FlowNode · Edge** — the node-graph editor for the Workflow / Pipeline / Ontology-Link builders (the biggest prior `workbench` coverage gap).
  - **RunLog** — hierarchical execution log (run → step → line).
  - **PivotTable** — cross-tab aggregation for dashboards.
  - **AssistantPanel** — the docked/floating global agent (composite).
  - **AppLauncher** — the app tile-grid overlay.
  - Manifest rebuilt; `build_manifest.py` `C` set extended in lockstep.
  - Added `preview.html` component-browser stories (token-only demos + When/Avoid/Anti/Where guidance) for all five, so they show in the browser.
- **New recipe R16 · Builder workbench shell** — the reusable `workbench` layout the Workflow, Pipeline, and dev-stage Replay/CUA builders share (generalizes the twin's replay-shell screens, which are too app-specific to be components). Also **reconciled the recipe cap**: the screen-intent schema and manifest recipe set were stuck at R1–R12 while `recipes.md` already defined R13–R15 — extended both to **R1–R16** (and the intake skill) so all recipes are actually declarable. Also filled the **preview.html Recipes group**: it demoed only 4 recipes (R1/R4/R6/R9); added token-only stories for the other 12 (R2/R3/R5/R7/R8/R10–R16) so all 16 show in the browser.
- **New harness CLI — `tools/synapse.py`** (the "tools" harness element): `lookup <name>` verifies a component/token/recipe/archetype is real and prints its rules — or the closest matches if not (prevents off-manifest components (RC6) and off-token values (RC3) *at generation time*, not just at the gate); `validate <intent.json>` and `gate` wrap `validate.py`; `list` prints a closed set. Wired into `screen-intake-skill.md` and `design-cycle.md` so the generating agent calls it. Stdlib-only; wrap-able as an MCP server later.
- **External-tools stance** documented in `design-cycle.md` (§Tools): the process is **strictly code-based** — no Figma/Canva or design-inspiration boards. The one sanctioned external tool is **bounded web reference research** — a *capability* (web search + viewing a live UI reference), tool-agnostic: fulfilled by whatever the generation tool provides or, at the floor, a human-supplied URL/screenshot, so it's not Claude-bound. The only hard tool dependency is bash (for `tools/synapse.py`). It may inform *structure/interaction* in Frame and maintainer refinement only — never visual style, never Generate directly, never Intake's data — and must clear the refinement rubric's Tier B (so it can't smuggle in consumer-app polish).
